# MT940 bank statement import

- [x] Sandboxed JS parser and mapper with exact decimal arithmetic, balance checks,
  dates, reversals, multiline narratives, and bounded input.
- [x] Repeat import detection; block ambiguous overlap without bank references.
- [x] Shared banking schema and nested importer/table; reuse an existing importer.
- [x] File upload in Integrations, bunq export guidance, normal preview/apply.
- [x] Parser/mapper tests and real runtime/browser fixture acceptance.
- [x] Validate a supplied real bunq export locally (272 transactions); retain
  only synthetic fixtures in the repository.
- [x] camt.053 (ISO 20022 XML) through the same importer, detected from the
  file contents, with its own sandbox-safe XML reader, synthetic fixture, unit
  tests, a QuickJS/WASM sandbox test and a browser step.
- [ ] Validate a real camt.053 export from a Dutch bank (ING, Rabobank, ABN AMRO
  and bunq all offer one) locally; the fixture is synthetic and does not
  establish bank-dialect compatibility.

No bank credentials, payment initiation or background bank access. Uploaded text
is runtime input, never embedded in stored plugin source. Import proposals and
approved data use the user's AtomicServer. Bank-specific extensions must fail
visibly if unsupported. Schema is per-drive, not yet a frozen global standard.

Sources: https://help.bunq.com/en-ie/articles/how-do-i-export-a-bank-statement
and https://bankrec.westpac.com.au/docs/statements/mt940/ .

## Evidence and remaining gaps

- Nine unit scenarios pass; real QuickJS/WASM certification passes. The browser
  fixture verifies error display, preview/apply, table rendering, reopening the
  installed importer and a repeat upload with zero proposed changes.
- Amounts are exact decimal strings. Numeric aggregation needs a shared exact
  decimal datatype and formatter; do not substitute floating point amounts.
- Legacy Loro heuristics reinterpret JSON-shaped text as resource arrays/objects.
  Import fingerprints now have an opaque prefix. JSON-shaped bank narratives
  are rejected visibly until the general text preservation problem is fixed.
- The file-input UI hook is still keyed `mt940` (installation localIds, the
  `plugin-schemas` key, the catalog shortname) although it now takes camt.053
  too; renaming would orphan existing installations. Generalize file input
  declarations when a non-bank file-based integration is added.
- Bank transaction identities are per export format, so an MT940 and a
  camt.053 export of the same period import as two sets of rows.
- Shared native localId guards reject concurrent duplicate creates on one server.
  Cross-node offline collision resolution and installation recovery remain open.
- A supplied real bunq export passed preview, apply and zero-change reimport in a
  disposable local drive on 2026-09-11. Repository fixtures remain synthetic.
- Installed importer discovery now refreshes after cold ontology hydration; the
  MT940 E2E covers reopening after full navigation.
